# Go2 导航栈修复记录（2026-11-18）

本文记录 2026-11-18 对 `nav` 包的一轮完整排查与修复，涉及四个问题：
**点云显示慢**、**2D Goal Pose 不走**、**禁倒车约束**、**左右摇摆**。
另附环境层面的两处修复（狗时钟同步、网卡/域自动选择）。

## 一、问题总览

| # | 现象 | 根因 | 修复位置 |
|---|------|------|----------|
| 1 | 2D Pose Estimate 后点云要等很久才显示 | AMCL `transform_tolerance` 0.1s 小于链路延迟 ~0.4s，TF 查询丢帧 | `config/localization.yaml` |
| 2 | 2D Goal Pose 后狗不动 | odom 时间戳跨时钟域 + local costmap 无障碍源 + 缺障碍 critic | `nav/odom_tf_bridge.py`、`config/costmap.yaml` |

## 二、问题 1：点云显示特别慢

### 现象
RViz 里点 "2D Pose Estimate" 给定初始位姿后，LaserScan 点云要过很久才出现。

### 根因
数据链路的实际延迟：

```
Mid360 点云 → 无线中继 → 笔记本        ~300ms
livox_scan 90ms 聚合窗口 + 40ms 回退     ~130ms
```

而 `amcl.transform_tolerance` 只有 **0.1s**。AMCL 用它标记 `map->odom` TF 的有效期；
RViz / costmap 按 `scan.header.stamp` 去查 `map->odom->base_link_level`，
查询时刻已超出 0.1s 有效窗口 → 报 `extrapolation into past` → 整帧丢弃。
TF buffer 要等新帧慢慢追上才恢复显示，所以表现为"启动特别慢"。

### 修复
`config/localization.yaml`：

```yaml
amcl:
  ros__parameters:
    transform_tolerance: 1.0    # 原 0.1
```

> 注意：`config/costmap.yaml` 里 global_costmap 早已在 11-18 把
> `transform_tolerance` 抬到 2.0（注释里记录了同一类丢帧问题），
> 但 AMCL 这一处漏改了。

## 三、问题 2：2D Goal Pose 不会走

三个原因叠加。

### 原因 A：odom 时间戳跨时钟域（主因）

`/utlidar/robot_odom` 的 `header.stamp` 来自狗主控时钟。狗开机时 RTC 未同步，
实测 epoch 只走了约 33 天（1970-02-11），与笔记本差 **数十年**。

Nav2 的 `controller_server` / `bt_navigator` 原先直接订阅这个 topic：

```yaml
odom_topic: "/utlidar/robot_odom"
```

内部 `MessageFilter` 按本机时钟过滤，stamp 严重过期的消息**全部被丢弃**
→ DWB 拿不到当前速度 → 轨迹从静止开始仿真 → 输出接近零速度。

同时 `progress_checker` 在 15s 内判无位移 → 触发 recovery → 永远在恢复。

### 原因 B：local_costmap 没有任何障碍源

11-18 早先的改动把 `local_costmap` 的 `obstacle_layer` 删了，只剩
`plugins: ["inflation_layer"]`。inflation 只能膨胀已有障碍，没有来源写入
→ **整张局部代价地图全 0**。

### 原因 C：DWB 没有障碍 critic

同一轮改动把 `ObstacleFootprint` 也删了，critics 只剩路径跟踪类。
所有轨迹障碍代价恒为 0，路径跟踪方向感不足，某些位姿下多个 critic 梯度
相互抵消 → 零速度输出。

### 修复

**1) `nav/odom_tf_bridge.py`：新增本机时钟重打版 odom**

原节点只发 TF（已重打时间戳），不发 odom 消息。现在额外发布 `/odom_local`：

```python
self.declare_parameter('publish_local_odom', True)
...
if self.publish_local:
    self.odom_pub = self.create_publisher(Odometry, '/odom_local', 20)
...
# cb() 中，TF 广播之后：
if self.publish_local:
    local_msg = Odometry()
    local_msg.header.stamp = t.header.stamp   # 本机时钟，与 TF 同源
    local_msg.header.frame_id = parent
    local_msg.child_frame_id = child
    local_msg.pose = msg.pose
    local_msg.twist = msg.twist
    self.odom_pub.publish(local_msg)
```

**2) `config/costmap.yaml`：改用 `/odom_local`**

```yaml
controller_server:
  ros__parameters:
    odom_topic: "/odom_local"     # 原 /utlidar/robot_odom

bt_navigator:
  ros__parameters:
    odom_topic: "/odom_local"     # 原 /utlidar/robot_odom
```

**3) `config/costmap.yaml`：local_costmap 加回 static_layer**

```yaml
local_costmap:
  local_costmap:
    ros__parameters:
      plugins: ["static_layer", "inflation_layer"]
      static_layer:
        plugin: "nav2_costmap_2d::StaticLayer"
        map_subscribe_transient_local: true
```

**4) `config/costmap.yaml`：DWB 加回 ObstacleFootprint**

```yaml
critics: ["RotateToGoal", "PathAlign", "GoalAlign", "PathDist", "GoalDist", "ObstacleFootprint"]
ObstacleFootprint.scale: 0.5
```

## 四、问题 3：禁倒车约束

要求：**不能后退；需要往后走时先原地转向**。

四处联动，缺一处就会被绕过：

| 层 | 文件 | 修改 |
|---|------|------|
| DWB 采样 | `config/costmap.yaml` | `min_vel_x: -0.15` → `0.0` |
| 指令桥限幅 | `nav/cmd_vel_sport_bridge.py` | `min_vx: -0.3` → `0.0` |
| 恢复行为插件 | `config/costmap.yaml` | `behavior_plugins` 移除 `backup` |
| 行为树 | `behavior_trees/*.xml`（两棵） | 删除 `<BackUp>` 节点 |

`behavior_server` 修改后：

```yaml
behavior_plugins: ["spin", "wait"]
```

行为树 recovery 轮换变为：清 costmap → Spin（1.0rad）→ Wait。
贴脸障碍时靠原地转向换方向再规划，绝不倒车。

## 五、问题 4：左右摇摆

### 现象
狗沿路径走时左右小幅摆动，方向不稳定。

### 根因
左、右两条候选轨迹得分接近时，DWB 每帧在两者间来回切换，没有"记住上一帧选择"的机制。

### 修复
`config/costmap.yaml` 加回 `Oscillation` critic：

```yaml
critics: [..., "ObstacleFootprint", "Oscillation"]
Oscillation.scale: 1.0
Oscillation.x_only: false
```

它记录上一帧选中的速度方向，对反向轨迹追加惩罚——一旦选了左就持续左，
选了右就持续右，不再逐帧摆动。

## 六、环境层面的两处修复

### 6.1 狗时钟同步

SSH 进狗（`unitree@192.168.123.18`，sudo 免密），把 RTC 从 1970 年同步到当前时间：

```bash
sudo date -s '2026-11-18 12:20:09'
sudo hwclock --systohc      # 写入硬件时钟，重启后保持
```

同步后误差约 0.38s。狗上没有 NTP/chrony，不会把时间改回去。

> 即使时钟已同步，`/odom_local` 仍然保留——狗重启后 RTC 可能再次漂移，
> 由桥接节点保证 Nav2 始终拿到同源时间戳。

### 6.2 网卡与域自动选择

原 `setup.sh` 写死了 `enp3s0`，与实机网卡名（`enp130s0` / `wlp129s0f0`）不符，
导致 `rmw_create_node: failed to create domain`。

现改为自动检测：

- 优先选已 UP 的 WiFi 网卡（`wlp*`）→ **域 1**
- 否则选已 UP 的有线网卡（`enp*`）→ **域 0**
- 同时把 ROS 发行版从 `foxy` 修正为 `humble`

```bash
# WiFi(wlp) 走域1，有线(enp) 走域0
if echo "$NET_IF" | grep -q '^wlp'; then
    export ROS_DOMAIN_ID=1
else
    export ROS_DOMAIN_ID=0
fi
```
